# Setting up the resume-generation workflow

This document walks through the one-time GitHub configuration needed for
`.github/workflows/generate-resumes.yml` to run successfully. It assumes
the LiteLLM/Ollama/Open WebUI stack from your `docker-compose.yml` is
already up and running somewhere.

## What this workflow does

On every push that changes `data/resume_data.json`, it calls your
self-hosted LiteLLM proxy to regenerate baseline SDE and SDET resumes,
plus a generic cover letter, in pdf/docx/txt/md/json, then opens a pull
request with the results. It never pushes straight to `main`, and it
never calls a paid API.

## Step 1: Decide how the workflow will reach LiteLLM

This is the one decision that affects everything else, so make it first.

GitHub's default hosted runners (`ubuntu-latest`) run on the public
internet. They cannot reach a container on your home LAN unless you
expose it. You have two options:

**Option A: Expose LiteLLM publicly (tunnel/reverse proxy)**
Put a Cloudflare Tunnel, Tailscale Funnel, or authenticated reverse proxy
in front of the `litellm` container's port, and use that public address
as `LITELLM_BASE_URL` in Step 2. Keep `runs-on: ubuntu-latest` in the
workflow file as-is.

**Option B: Self-hosted GitHub Actions runner (recommended for a home LAN)**
Install a GitHub Actions runner on a machine on the same network as your
Docker stack, so nothing needs to be exposed to the internet at all.

1. In the repo: **Settings -> Actions -> Runners -> New self-hosted runner**.
2. Follow GitHub's generated setup commands on a machine that can reach
   the `litellm` container.
3. Run the runner as a service so it survives reboots.
4. In `.github/workflows/generate-resumes.yml`, change `runs-on:
   ubuntu-latest` to `runs-on: self-hosted`.
5. `LITELLM_BASE_URL` (Step 2) can then just be a plain LAN address, e.g.
   `http://192.168.1.50:4000`.

## Step 2: Add repo secrets

**Settings -> Secrets and variables -> Actions -> Secrets -> New repository secret**

| Secret name | Value |
|---|---|
| `LITELLM_BASE_URL` | The address from Step 1, pointing at `${LITELLM_PORT}` -- **not** Open WebUI's `${UI_PORT}` |
| `LITELLM_API_KEY` | Same value as `LITELLM_MASTER_KEY` in your Docker stack's `.env` |

## Step 3: Add a repo variable

**Settings -> Secrets and variables -> Actions -> Variables -> New repository variable**

| Variable name | Value |
|---|---|
| `LITELLM_MODEL` | `ollama/${MODEL_NAME}`, using the actual value of `MODEL_NAME` from your stack's `.env` (e.g. `ollama/llama3.1:70b`) |

> **Keep this in sync manually** with `MODEL_NAME` in the Docker stack's
> `.env` -- nothing links them automatically. A mismatch is the most
> common cause of a "model not found" failure.

Optionally, set `OLLAMA_NUM_CTX` (also a Variable) if your GPU can't hold
the default 16384-token context window for the model you're running.

## Step 4: Place the knowledge base file

The workflow expects it at `data/resume_data.json` in this repo.

## Step 5: Test it manually before relying on the automatic trigger

1. **Actions** tab -> **Generate resumes and cover letter** -> **Run
   workflow** (uses `workflow_dispatch`, no need to touch
   `data/resume_data.json` yet).
2. Watch the run -- the script prints a per-variant prompt-size estimate
   and final page count/font size to the log.
3. If it succeeds, a PR titled *"Auto: regenerate resumes/cover letter
   from resume_data.json"* appears. **Read the diff in `generated/`
   before merging** -- local-model output can drift more than a hosted
   model's, so this first run is worth a close look.

## What gets generated

| File | Contents |
|---|---|
| `Dennis Dole Resume (SDE).{pdf,docx,txt,md,json}` | SDE-framed resume, targeted at 2 pages |
| `Dennis Dole Resume (SDET).{pdf,docx,txt,md,json}` | SDET-framed resume, same content, SDET title/summary framing |
| `Dennis Dole Cover Letter.{pdf,docx,txt,md,json}` | Generic cover letter (not company/role-specific) |
| `README.md` (repo root) | The GitHub profile page. Generated by its own separate LiteLLM call, which fills in `data/readme_template.md` using `resume_data.json` |

## Troubleshooting

| Symptom in the Actions log | Likely cause | Fix |
|---|---|---|
| `LITELLM_BASE_URL and/or LITELLM_API_KEY are not set` | Secrets missing/misnamed | Re-check Step 2 |
| `Could not reach LiteLLM at ...` | Runner can't reach the instance | Revisit Step 1 |
| `LiteLLM returned an error (HTTP 401...)` | Wrong API key | `LITELLM_API_KEY` must match `LITELLM_MASTER_KEY` exactly |
| `LiteLLM returned an error (HTTP 400...)` mentioning the model | Model name mismatch | `LITELLM_MODEL` must match what LiteLLM was started with |
| `Model failed to produce valid JSON after 2 attempts` | The local model isn't following the output-format instructions even after a corrective retry | Try a larger/more instruction-tuned model |
| A resume renders at >2 pages (script prints a `WARNING:`) | Knowledge base has grown beyond what fits at the smallest readable font tier | Content decision, not something to silently auto-trim -- see `PDF_TIERS` in `generate_resumes.py` |
| Workflow times out after 15 minutes | Instance hung, overloaded, or unreachable but not erroring cleanly | Check `docker compose logs ollama litellm` |
